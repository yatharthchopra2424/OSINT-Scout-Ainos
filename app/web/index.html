OSINT Scout account monitoring for Sales & Alliances

The agent, one node at a time

A run walks these eight steps in order. Three of them involve no model at all — the model reads and extracts, plain Python decides and reports. If the verify gate keeps fewer than three facts, the graph loops back to retrieve once with a wider k, and only once.

Model check

Calls the chat model and the embedding model for real and reports what came back. With no NVIDIA API key the app still runs end to end on its control extractor and lexical embeddings — that is what lets the eval harness run in CI with no secrets.

Run log

    

      One JSON line per event, written by the nodes as they execute. This is the audit
      trail: which node saw what, how long it took, and the reason every dropped fact
      was dropped.
    

    

      

      
    

    

  







  

    
Scoring rules

    

      The language model never produces the score. It extracts facts; this file decides
      what they are worth. Every point in a score traces back to a rule here and to the
      URL the fact came from, and the same facts always produce the same number. Edit
      and save — it is validated before it is written.
    

    
    

      
      
      
    

  







  

    
Eval harness

    

      Runs the pipeline against a frozen gold set — six synthetic accounts, no network.
      Each account runs three times: once to measure, twice more to prove the result is
      stable and that an identical re-run reports no phantom changes. The same command
      runs in GitHub Actions on every push, and a failed gate fails the build.
